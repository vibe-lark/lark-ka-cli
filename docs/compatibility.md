# 兼容性与验证范围

本项目为 Node.js 原生实现，要求 Node.js >=22，安装包不含 Go 源码、Go 内核或平台二进制。

## 命令范围

- 原工程静态导出的 315 个快捷命令定义均有 Node 处理入口。
- 252 个元数据 API 方法由统一请求层执行，保留原项目的本地元数据覆盖项。
- 配置、Profile、授权、Skill、版本更新、补全、MCP 和事件命令均提供 Node 实现。
- 通用 API 支持 JSON 参数、分页、multipart 文件上传及二进制输出。
- 机器可读明细由 `npm run compatibility` 生成到 `docs/compatibility.json`。

以上表示命令入口和实现映射覆盖，不表示原 Go 版的全部选项、第三方库输出及边界行为已经逐项验证一致。

## 已知差异

| 项目          | 当前行为                                                                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| jq            | 支持路径、索引、数组展开和路径管道；不支持完整 jq 语言。复杂表达式明确报错。                                                                                                                |
| 文档          | 原生 docx 支持基础富文本、列表、表格和局部编辑；复杂 XML、合并或复杂样式、部分定位和块操作需配置客户实际可用的 docs_ai/MCP。公有版默认 MCP，显式 v2 选择 docs_ai；私有化示例选择原生 docx。 |
| 文档同步      | 需指定明确冲突策略，未实现交互式 ask；重名目录不自动复制改名。                                                                                                                              |
| 文件下载      | 妙记下载目录和批量输出已迁移；文件名仍以 token 命名，未完整复刻所有响应头驱动的命名规则。                                                                                                   |
| 结果展示      | 已实现主要 JSON/CSV/表格、Base Markdown 输出；罕见消息类型的格式化和部分字段归一化不保证逐字一致。                                                                                          |
| Markdown diff | 提供统一 diff，但 hunk 分组可能与原 Go 第三方库不同。                                                                                                                                       |
| 凭据与插件    | 使用本项目独立的受限本地文件和员工会话归档；不复用 Go 系统钥匙串、编译型插件。Go auth-sidecar 环境会明确拒绝启动，避免绕过隔离。                                                            |
| 用户事件      | 已迁移会议、纪要、妙记和画板的用户注册及清理，并按接收人过滤；老私有版本缺少接收人字段时不输出该事件，需按客户真实 payload 对齐。                                                           |
| 事件运维      | WebSocket 在 Node 进程中运行；与原 Go 共享事件总线、发布状态检查及全部细节重试行为尚非完全等价。                                                                                            |

## 已做验证

- 使用 Node 22 实际执行本地测试。
- 测试覆盖参数和错误契约、授权回调与 state、刷新及多员工会话并发、请求域名与 MCP 鉴权边界、dry-run、主要业务工作流、事件身份过滤、文件传输和输出安全。
- 生成 npm 安装包，在独立临时目录安装并执行版本、Schema 和消息 dry-run 检查。
- 安装包内容检查排除了 Go 文件、原生内核、真实凭据和历史工作记录。

测试使用本机模拟服务和临时配置，没有调用中国海油真实 API。客户环境地址、App ID、已批准 Scope、回调与实际私有化接口版本确认后，还需要进行真实联调。
